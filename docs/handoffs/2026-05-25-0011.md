## Decisiones tomadas

Decisiones técnicas no obvias de esta sesión (no documentadas en commits ni en CLAUDE.md/ARCHITECTURE.md/FUNCIONAL.md):

- **Migración de T8 (observability) a `@observe` decorator de Langfuse v2** + auto-callback de LiteLLM, sustituyendo una implementación previa con `_make_tracer` custom + `try/except/finally`. La doc oficial de Langfuse v2 (verificada en `docs.langfuse.com/sdk/python`) provee `@observe` que captura input/output/latency/errores automáticamente, hace auto-nesting via contextvars, soporta async, y es tolerante a fallos del cliente por diseño. ~10 LOC funcionales vs ~35 LOC custom. Las "defensas D1/D2" que se habían diseñado para el custom son inherentes a `@observe` + lazy init del SDK. Se descarta upgrade del server a v3/v4 (requeriría `clickhouse + redis + langfuse-worker` adicionales).

- **`init_observability()` explícito** desde `app.main.py` en lugar de side effect al import en `langfuse_client.py`. Razón: el side effect al import mutaría el estado global de `litellm.success_callback` apenas alguien importe el módulo (incluyendo tests que mockean LiteLLM), riesgo real de test pollution si CI alguna vez tiene credenciales Langfuse en `.env`. La función explícita deja la decisión de "cuándo arrancar observability" en manos del orquestador.

- **`time_utils.utcnow()` helper centralizado** en `backend/src/app/time_utils.py` para reemplazar `datetime.utcnow()` (deprecado en Py 3.12+) en 7 sitios. Alternativa descartada: lambda inline `default_factory=lambda: datetime.now(UTC)` repetida en cada modelo. El helper es punto único de cambio, función nombrada testeable, y no duplica código. Ruff auto-aplicó `from datetime import UTC, datetime` (alias Python 3.11+).

- **`ENV PYTHONPATH=/app/src` en el backend Dockerfile** en lugar de declarar `app` como paquete propio con `[build-system]` en `pyproject.toml`. Razón: sin este ENV el contenedor backend salía con `ModuleNotFoundError: No module named 'app'` porque el Dockerfile copia las fuentes en `/app/src/app/` con `WORKDIR /app` pero uv lo instala editable sin registrarlo en sys.path. El refactor a paquete formal con `[build-system]` requeriría tocar `pyproject.toml` + tests + scripts (cascada). El ENV resuelve con 1 línea. Refactor a paquete formal queda como follow-up post-F1.

- **`"packageManager": "pnpm@10.10.0"` pineado en `frontend/package.json`** en lugar de upgrade del Dockerfile a `node:22-alpine`. Razón: sin la declaración, Corepack baja pnpm 11.x (último por defecto) que requiere Node 22+, lo que rompía con `node:20-alpine` (`ERR_UNKNOWN_BUILTIN_MODULE` durante `pnpm install --frozen-lockfile`). pnpm 10.x es compatible con `lockfileVersion: '9.0'` del lockfile y con Node 20. Pin del packageManager es solución mínima y reproducible; upgrade de Node implicaría más cambios.

- **Verificación end-to-end real es parte irrenunciable del cierre F1.** La suite pytest + ruff no fue suficiente: ejecutar `docker compose up -d --build` reveló 2 defectos (PYTHONPATH backend, pnpm packageManager frontend) que llevaban en `main` desde T3 (commit `c826b8a`) sin detectarse. Documentado como aprendizaje para futuras tareas: si el ticket toca infra, hay que arrancar de verdad antes de declarar hecho.
